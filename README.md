# Пульс направления

Единый дашборд для руководителей групп направления продаж.
Спецификация: `docs/superpowers/specs/2026-11-09-np-sr-dashboard-design.md`.

## Каждое утро

1. Двойной клик по **«Запустить админку.bat»** — админка откроется в браузере (работает только на этом компьютере).
2. **«Собрать отчёты»** — админка сама найдёт самые свежие отчёты в сетевых папках, посчитает показатели
   и покажет сводку «что подтянулось».
3. Проверьте сводку и нажмите **«Опубликовать»** — данные зашифруются и уйдут на GitHub Pages.
   Руководители увидят обновление по той же ссылке через 1–2 минуты.

Нет доступа к сети — перетащите файл отчёта на его строку в админке.

## Первая настройка

- Для каждого из 8 отчётов вставьте путь к сетевой папке (например, `\servereports\…`). Пути запоминаются.
- В блоке «Ссылка для руководителей» укажите адрес сайта на GitHub Pages и скопируйте ссылку с кодом доступа.
- Нормативы и порог «гадкого утёнка» редактируются там же и попадают в следующую публикацию.

## Безопасность

- В репозиторий попадают только `web/public/data/dashboard.enc.json` (AES-GCM 256, ключ — PBKDF2 от кода
  доступа) и открытый `version.json`. Исходные Excel-файлы, история и настройки админки лежат в
  `%LOCALAPPDATA%\npsr-dashboard` и в git не попадают — это проверяет `scripts/check_public.py`
  (хук перед коммитом и проверка в CI).
- Код доступа передаётся в ссылке после `#` и не уходит на сервер. Это защита от случайного доступа из
  интернета, а не от сотрудников со ссылкой. Если ссылка утекла — «Сменить код доступа», опубликовать,
  разослать новую ссылку.

## Разработка

```bash
cd admin && .venv/Scripts/python -m pytest -q      # админка и парсеры (образцы отчётов — в корне проекта)
cd web && npm test && npm run build                 # дашборд
```
