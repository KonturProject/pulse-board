# Вкладка «Динамика» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** экран `#/dynamics` (и `#/dynamics/<группа>`) с трендом за 4 недели по группам и менеджерам: мини-график, прирост за неделю, итог недели (место, сильные/провалы).

**Architecture:** только сайт (`web/`). Чистая логика в `web/src/dynamics.ts` считает точки, приросты и итоги из уже опубликованного payload; `ui/Spark.tsx` рисует мини-график; `screens/Dynamics.tsx` — экран; фильтр скрытых сотрудников выносится из `Group.tsx` в `hidden.ts` и переиспользуется. Админка и формат данных не меняются.

**Tech Stack:** React 19 + TypeScript, Vitest + Testing Library, SVG без библиотек.

**Spec:** `docs/superpowers/specs/2026-11-15-dynamics-design.md`

## Global Constraints

- Показатели: `MAIN_METRICS` для групп; для менеджеров — `MAIN_METRICS.filter(m => !m.groupOnly)`.
- «Почти без изменений»: `|now − prev| < 0.03 · |now|` → `flat`.
- Все показатели «больше — лучше».
- Неполная текущая неделя: дневные показатели сравниваются с прошлой неделей по тот же день недели (ключ `${prevWeek}~${день}`), недельные — неделя с неделей.
- Ран-рейт сравнивается как есть; на графике метка смены месяца.
- Скрытые на экране группы сотрудники (localStorage `npsr-hidden:<группа>`) не показываются, цифры групп пересчитаны `withoutEmployees`.
- Кнопка «Динамика» — `<a className="view-btn" href="#/dynamics">` в ряду `nav.views` главного экрана.
- Палитра и стили — существующие токены `web/src/styles.css`.

## Review Focus

1. Короткая история (данные только за 1–2 недели окна) → график из имеющихся точек, прирост «—», без падения (тест в Task 1).
2. Текущая неделя только с понедельником → сравнение понедельник с понедельником (тест в Task 1).
3. Показателя у группы нет (СР9 × «Попытки 300+») → серая ячейка «—» (тест в Task 3).
4. Сотрудник скрыт на экране группы → его нет среди менеджеров в «Динамике», цифры группы пересчитаны (тест в Task 3).
5. Смена месяца внутри окна → метка на графике ран-рейта (тест в Task 2).

### Task 1: Логика динамики

**Files:**
- Create: `web/src/dynamics.ts`, `web/tests/dynamics.test.ts`

**Interfaces:**
- Consumes: `Payload` (`data.ts`), `Sel`, `cellValue`, `cellZone`, `GROUP_KEYS` (`view.ts`), `rankGroups` (`rating.ts`), `weekdaysOf` (`format.ts`), `METRIC` (`metrics.ts`).
- Produces:
  - `type Trend = 'up' | 'down' | 'flat' | 'none'`
  - `type Change = { points: (number | undefined)[]; now?: number; prev?: number; diff?: number; trend: Trend }`
  - `change(p: Payload, metric: string, entity: string): Change` — `points` по `p.weeks` (значение `values[metric][week][entity]`), `now` = точка последней недели; `prev` — см. алгоритм ниже.
  - `lastDay(p: Payload): string | null` — последний день с данными в последней неделе окна (`p.days[lastWeek].at(-1)`).
  - `type Summary = { place?: number; dPlace?: number; good: number; dGood: number; bad: number; dBad: number }`
  - `groupSummary(p: Payload, group: string): Summary` — по `rankGroups` для `{week: last, day: null}` и `{week: prev, day: null}`; `dPlace = prevPlace − place` (положительный — поднялся).
  - `employeeSummary(p: Payload, emp: string, peers: string[]): Summary` — без места; число зон `good`/`bad` по показателям менеджера (`cellZone` с `peers`) на последней и предыдущей неделе.

Алгоритм `prev` (единственное, что не определяется сигнатурой):

```
lastW = weeks[-1], prevW = weeks[-2]; d = lastDay(p)
if metric daily and d:
    i = weekday index of d (0 = Monday)
    same = weekdaysOf(prevW)[i]
    k = latest day of p.days[prevW] that is <= same
    prev = k ? values[metric][`${prevW}~${k}`][entity] : undefined
else:
    prev = values[metric][prevW][entity]
```
